  <action>
Create four POSIX-compatible shell wrappers under `src/templates/codex/hooks/`.

`user-prompt-submit.sh`:
- read stdin into `PAYLOAD`
- resolve `ROOT="$(git rev-parse --show-toplevel 2>/dev/null || pwd)"`
- if `$ROOT/.codewiki/hooks/pre-wiki-context.sh` is executable or readable, pipe the payload into `bash "$ROOT/.codewiki/hooks/pre-wiki-context.sh"`
- exit 0 always
- plain stdout is allowed here because Codex treats it as developer context for `UserPromptSubmit`

`pre-tool-use.sh`:
- read stdin and resolve `ROOT`
- do not print shared hook context to stdout
- run only lightweight guardrail checks if implemented; for the initial wrapper, return `{}` or empty stdout and exit 0
- include a comment stating Codex ignores plain stdout for `PreToolUse`

`post-tool-use.sh`:
- read stdin and resolve `ROOT`
- call `bash "$ROOT/.codewiki/hooks/post-verify.sh"` with the payload on stdin
- if output is non-empty, emit JSON:
  `{"hookSpecificOutput":{"hookEventName":"PostToolUse","additionalContext":"..."}}`
- escape backslashes, quotes, tabs, carriage returns, and newlines safely before inserting into JSON
- emit `{}` when there is no shared hook output
- exit 0 always

`stop.sh`:
- read stdin and resolve `ROOT`
- if payload contains `"stop_hook_active":true` or `"stop_hook_active": true`, emit `{}` and exit 0
- call `bash "$ROOT/.codewiki/hooks/session-end.sh"` with the payload on stdin
- if output is non-empty, emit `{"decision":"block","reason":"..."}` using escaped output
- emit `{}` when there is no follow-up output
- never print plain text because Codex `Stop` requires JSON stdout on exit 0
  </action>
  <acceptance_criteria>
    - Each wrapper starts with `#!/bin/sh`
    - `user-prompt-submit.sh` contains `pre-wiki-context.sh`
    - `pre-tool-use.sh` contains `PreToolUse` and `plain stdout`
    - `post-tool-use.sh` contains `post-verify.sh`, `hookEventName`, and `PostToolUse`
    - `stop.sh` contains `session-end.sh`, `stop_hook_active`, and `"decision":"block"`
    - Every wrapper contains `git rev-parse --show-toplevel`
  </acceptance_criteria>
